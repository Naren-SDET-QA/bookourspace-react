# BookOurSpace Evolution WhatsApp QA

This is a development-only WhatsApp Web/Baileys setup. It uses a separate
Evolution API container, separate PostgreSQL/Redis volumes, and the fixed QA
recipient 9966191813. It does not use the expired Meta token, production
WhatsApp number, customer database, inbound receiving, or production booking
notifications.

## Start the local service

The local secret file is ignored by git. If it does not exist, create it from
.env.evolution.example and set both values to long random strings.

    cp .env.evolution.example .env.evolution.local
    docker compose --env-file .env.evolution.local -f docker-compose.evolution.yml up -d

The app-side values belong in .env.local:

    EVOLUTION_API_URL=http://localhost:8080
    EVOLUTION_API_KEY=<same value as .env.evolution.local>
    EVOLUTION_INSTANCE=bookourspace-dev
    EVOLUTION_DEV_TEST_ENABLED=1
    EVOLUTION_DEV_TEST_RECIPIENT=9966191813

## Pair a separate test sender

Create the instance with the Evolution API key:

    curl -sS -X POST http://localhost:8080/instance/create \
      -H 'Content-Type: application/json' \
      -H 'apikey: <EVOLUTION_API_KEY>' \
      -d '{"instanceName":"bookourspace-dev","integration":"WHATSAPP-BAILEYS","qrcode":true}'

Open the returned QR code, then on the separate WhatsApp sender phone use
WhatsApp > Linked devices > Link a device. Do not pair a production sender.

## Send the QA pack

The application endpoint is development-only, admin-authenticated, fixed to
the configured QA recipient, and requires confirmSend: true. It sends four
standard text notifications and the branded QR/PDF media generated by the
existing BookOurSpace templates.

    { "to": "9966191813", "confirmSend": true }

No production route calls this provider. Keep EVOLUTION_DEV_TEST_ENABLED=0
until the local Evolution instance is paired and the QA run is intentionally
authorized.
